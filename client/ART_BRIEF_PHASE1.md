# 青竹·九州切片 · Phase 1 美术与集成设计规范 (ART_BRIEF_PHASE1)

> **设计主责**：Antigravity (Godot 前端、设计系统、视觉层级、动效与可读性主导)  
> **资产制作**：GPT (严格按本 Brief 规格生成无文字、无硬阴影、纯净透明通道的工笔水墨水彩切片)  
> **适用范围**：Phase 1 战术手牌、军团编成、3路×2排推演回放系统及后续扩展

---

## 1. 总体视觉愿景与设计哲学

1. **水墨纸雕 × 宣纸沙盘**：
   - 整体界面延续《青竹》的“浅暖宣纸底色（`#f6efe2` / `#efe7d5`）+ 乌木边框（`#231c17`）+ 烫金勒线（`#c9a227`）+ 朱砂（`#b83b32`）/ 墨蓝（`#1e3a5f`）双阵营对决”视觉基调。
   - 战斗场景不是暗黑写实战场，而是**具有东方古雅美感的“推演沙盘/屏风折页”**，克制、洗练、信息层级清晰。
2. **64px 极致可辨剪影**：
   - 无论在 720×514 手机横屏（战斗单位实际渲染尺寸约 56px–72px）还是 1400×1000 平板端，必须做到**不看文字、不看血条，仅凭剪影轮廓 0.2 秒内识别兵种**。
3. **阵营色克制原则（红线）**：
   - **绝对禁止将单位整体染成单色或“红皮/蓝皮”**（如红衣服小人打蓝衣服小人），这会严重破坏水墨历史画风的高级感。
   - 单位身体均采用自然原色：米白麻布、赭石熟褐皮革、生铁冷光、青铜光泽。
   - **阵营色（朱砂红、墨蓝、竹青、藤黄）只上在：头盔缨穗、背后一杆靠旗（背旗）、脚底水墨光环微光，以及战报印章！**

## 2. 战场空间布局与定位规格 (Battlefield Metrics)

战场采用标准的 **3 路 (Lanes) × 2 排 (Rows)** 横向对决阵式，攻方在左，守方在右。

```text
 攻方阵地 (左)                                                守方阵地 (右)
+-----------------------------------------------------------------------------------------+
| [顶部 HUD]: 关隘/城池名称 | 城墙耐久条 (1000/1000) | 回放候数 (00/60) | 播放/倍速/跳过  |
+-----------------------------------------------------------------------------------------+
| [器械区] | [攻方后排] | [攻方前排] |   【中央交锋带】   | [守方前排] | [守方后排] | [城墙城门] |
| (x≈0.04) | (x≈0.18)   | (x≈0.32)   |    (x≈0.45~0.55)   | (x≈0.65)   | (x≈0.78)   | (x≈0.88~1) |
|          |            |            |                    |            |            |            |
| 上路 L1: |  后排单位  |  前排单位  |       ⚔️交火       |  前排单位  |  后排单位  |            |
|          |            |            |                    |            |            |   高耸石墙 |
| 中路 L2: |  后排单位  |  前排单位  |       ⚔️交火       |  前排单位  |  后排单位  |   木构城门 |
| [投石/撞车]           |            |                    |            |            |   (纵贯3路)|
| 下路 L3: |  后排单位  |  前排单位  |       ⚔️交火       |  前排单位  |  后排单位  |            |
+-----------------------------------------------------------------------------------------+
| [底部 HUD]: 攻方兵力总条 (红) vs 守方兵力总条 (蓝) | 阵亡/存活统算 | 战报悬浮出令提示  |
+-----------------------------------------------------------------------------------------+
```

### 2.1 坐标与尺寸基准

- **战场画布比例**：动态铺满 viewport 中央（约占高宽比 16:9 或 2:1）。
- **战道划分**：
  - 垂直均分 3 条战道：`Lane 1` (上路，`y=16.6%`)、`Lane 2` (中路，`y=50.0%`)、`Lane 3` (下路，`y=83.3%`)。
- **单位卡与 Sprite 尺寸**：
  - **手机端 (720×514)**：Sprite 渲染为 64×64 至 72×72，底部配 8px 血条与数字，总高约 62px。
  - **平板端 (1400×1000)**：Sprite 渲染为 96×96 至 112×112，总高约 90px。
- **锚点规则 (Anchor Point)**：
  - **脚底中心对齐**：Sprite 锚点统一为 `(0.5, 0.90)`，即单位双脚站立点正中。
  - 严禁以图像中心对齐，否则待机/攻击/受击切帧时脚底会发生上下抽搐或漂浮。
- **前后排层级与朝向 (Z-Order & Facing)**：
  - **朝向**：攻方（左侧）所有单位默认朝右（`flip_h = false`）；守方（右侧）所有单位引擎自动水平镜像（`flip_h = true`），正面相对。
  - **前后排遮挡关系**：
    - 前排单位 `z_index = lane * 10 + 2`；
    - 后排单位 `z_index = lane * 10 + 1`；
    - 确保前排在透视上自然遮挡后排足部或长兵器。
- **器械与城门位置**：
  - **攻方重械 (Siege Engine)**：位置固定在攻方阵后（`x ≈ 0.04 * Width`，居中对齐中路），仅在攻方具备器械时渲染。
  - **城门与坚壁 (Gate & Wall)**：位置固定在最右侧（`x ≈ 0.88 * Width` 到 `1.0 * Width`），纵贯 3 路全高，带有石块基座、朱漆城门与箭垛瓦檐。

**背景生成硬性约束**：
1. **尺寸**：统一 `1920×1080` 或 `2560×1440`，JPG/PNG（无透明度亦可，或带宣纸肌理）。
2. **色度与明度**：整体明度不低于 85%，对比度低于 30%。它必须是**退后衬托单位的“纸上淡彩”**，绝不能喧宾夺主。
3. **严禁绘制死物**：严禁在背景上绘制具体的兵马、房屋、尸体、旗帜或文字。

### 4.2 三态动作定义 (Idle / Attack / Hit)

每个兵种生成 3 张独立透明底单帧 Sprite：

1. **`idle` (待机/布阵)**：
   - 姿态端正蓄势，兵刃收敛身侧，构图居中稳重。
2. **`attack` (攻击/进击)**：
   - 具有明确的前倾动势：骑兵扬蹄纵跃、盾兵顶盾撞击前冲、弓兵拉满弓弦向右瞄准、枪兵双手平刺挺进。
3. **`hit` (受击/挫退)**：
   - 身体重心微后倾仰，兵器或盾牌偏斜，无血腥残肢，体现“受震受阻”感。

### 4.3 阵营归属呈现规范（非全身着色）

- **攻方（朱砂红 `#b83b32`）**：
  - 骑手/武卒头盔红缨鲜亮；
  - 背插一杆红色小令旗（背旗），迎风展动；
  - 单位脚底带有半透明朱砂水墨晕染光圈（程序叠加）；
  - 卡片顶部加盖朱砂阵营印章。
- **守方（墨蓝 `#1e3a5f`）**：
  - 头盔系墨蓝布巾或蓝缨；
  - 背插墨蓝小令旗；
  - 脚底带有半透明墨蓝水墨晕染光圈（程序叠加）；
  - 卡片顶部加盖墨蓝阵营印章。

### 8.1 GPT 生产五大严禁项 (Hard Constraints)

1. **严禁文字（除阵营旗规定单字古篆外）**：图标、单位、背景中一律不得含有汉字、拼音、英文或数字。
