# 布局复核

## 结论

- 真正同构的是操作关系。地图常驻，点城打开底部抽屉，确认覆盖在同一战场上下文之上。战报和回放有独立页面，能返回沙盘。这条链路可以保留。
- 信息层级相似的是顶部身份、资源、截止时间，边缘的辅助入口，底部的高频导航。相同位置出现相似信息，并不意味着空间结构相同。
- 明显不同的是地图和 UI 争夺空间的方式。平板实图中纸卷边框和左右深色栏为地图划出了独立矩形，地图宽约占 78%，底部居中导航又占一条案台空间。brief 的对照结构让地图延伸到屏幕边缘，HUD 和贴边导航盖在地图之上。前者像桌游案台，后者像从战场上方观察。把侧栏调透明但仍预留同样的宽度，解决不了这个差异。

评分只评布局相似度。1 为仅题材或功能名称相近，3 为主要操作层级相近但空间组织有差异，5 为视口、控件锚点和操作层级均高度接近。以 brief 给出的参照结构为基准，不对特定游戏版本作逐像素比较。已目视检查指定截图和标注图，未运行客户端。标注用于解释意图，实图用于判断当前表现。

## 最优先的 5 个修改

1. **先重排主地图视口。** 保留 C 水彩，画卷扩到安全区边缘，把辅助按钮移到地图上层的少量锚点，底部导航贴边。给文字保留稳定的实色或高对比底，避免为了做半透明而难读。
2. **统一真实路线和点城操作。** 以游戏邻接关系为准，只让可走路线承担交互含义。抽屉首屏优先可行动项，打开时把目标、城名与所选路线移到抽屉上方。用最低节点在手机横竖屏各验一次。
3. **把确认页改成下令摘要。** 让学生一眼看出目标、会消耗或覆盖什么、何时生效及何时能撤改。胜负仍未结算时用预计效果表述。
4. **让战报与回放按事件衔接。** 首屏先讲个人结果，再讲地图变化。点事件直达对应回合与节点。没有结算时展示备战状态。
5. **减少外围页面的平铺卡片。** 登录收紧表单并去掉背景中似控件的空槽，阵营首屏突出本方目标，赛季首屏突出当前周和下一节点。页签随实际内容增加。

## 不要做什么

- 不复制商业游戏 UI、素材、文案。
- 不为了相似度缩小字号和触控区，或让低对比半透明面板覆盖复杂地形。
- 不用占位排行榜和装饰页签填补数据缺口。先以学生能独立找到城、确认军令、解释战报为准。
