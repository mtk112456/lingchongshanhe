# 三方设计 consultation · GPT 美术与终审

## 结论

**不加抽卡，不接班级盲盒。** 城池造型以《江南百景图》所代表的环境叙事为主，地图操作以《率土之滨》《三国志·战略版》的信息分层为参照，文脉卡借《忘川风华录》的立绘留白。**60–100 人在表现层可行，前提是地图仍只画 13 个城池对象。** 实际同时提交与结算能力由 OpenCode 压测验证。

## 1. 参考与模仿边界

| 模块 | 借鉴方式 |
|---|---|
| 地图城池 Sprite | 学《江南百景图》用屋顶、地形与小物讲清地点。每城只留一个远看主轮廓，小物独立分层，到近景再出现。适合横屏小视口和 AI 批量生产。 |
| 城池抽屉 | 学率土/三战按选中城组织归属、守备、相邻和主操作，保持地图上下文。纸卡和图标采用本项目 C 版。 |
| 易主反馈 | 借策略游戏即时可辨的旗色切换，再借原神/崩铁的短反馈节奏。用本项目印章做约 0.8–1.2 秒演出，允许跳过，战报能看前后归属。 |
| 城望成长 | 借江南城镇用灯、旗和陈设体现变化，一座城共用一张主体图，状态由少量附件表达。 |
| 文脉卡与图鉴 | 借忘川的主体构图、无悔华夏的主题导览。诗句、出处和解锁条件由界面渲染，材料用原创图。 |

文明/Unciv 的邻接可参考，密集格子和科技树会提高学习成本。实时集结、长养成、3D 镜头和卡牌稀有度都超出本轮需要。只借层级、细节密度与反馈节奏，具体构图、图标、按钮、文案、音效和素材均自行制作。

## 2. 抽卡判断

随机获取会把学生的积分差、参与频率和运气叠加成可展示的稀有度差异。即使奖励纯外观，也容易形成班级攀比。美术还要持续供给奖池、重复品和稀有度演出，成本会挤掉当前更需要的城池与可读性验证。班级旧盲盒有独立用途，避免把其奖励预期、订单与库存带进游戏，因此不接 `shop_blind_box`。

长期目标用可预期的收集。文玉直购表情、皮肤、军旗、头像框和战报印章，固定价格，先看全量预览。地图外观购买不能改变阵营标记。文脉卡由守城、发现地标或赛季里程碑解锁，图鉴展示缺哪张和怎么拿。赛季给参与纪念，冠军另有外观标识。转入、缺席或阵营失利者可通过后续文脉任务补齐收藏。教师可按统一规则发活动纪念品，并保留记录。首测暂用免费确定性解锁，先观察学生是否愿意回来下令。

## 3. 城池设计

长安是中立王城和赛季目标。四个起点为凉州、邺城、成都、建业，大营是战术身份，可以叠加边塞、田园或水乡主题。其他城用关隘、渡口、文脉城、田园、水乡等类别做轮廓与交互提示。战术数值由已确认的规则驱动，画面不暗示未接入的加成。

| 垂直切片 | 环境与地标 | 先验什么 |
|---|---|---|
| 长安 | 关中平原、渭河与远秦岭，大雁塔居中，横向宫阙托底 | 中立王城在 0.35× 是否独立于纸阵营藤黄，四条中枢路线是否清楚 |
| 凉州 | 河西戈壁、干冷山脊，低宽夯土墙配雷台铜奔马 | 与长安高塔在灰阶 64px 下是否仍易区分 |
| 洛阳 | 伊洛河、牡丹与石壁，阶梯状龙门石窟作主剪影 | 验证浅台地暗衬和非关楼类文脉城，兼做文脉卡样板 |
| 建业 | 秦淮水道、柳岸水汽，夫子庙横檐加低位灯船 | 验证水面上城名和行军线对比，纸阵营与王城金色分离 |

每城一个 512×512 透明主体，底边中心贴地，另有 64px 剪影、128px 结构、256px 细节档。四阵营色仅上旗、细环和印章，旗形和选中态同时承担识别。中立用灰旗，王城双环和高塔为固定身份，易主后另挂占领旗。普通选中用临时单环和相邻线，易主用旗帜换色与短印章反馈。城望连续控制 3 天加灯旗，7 天加纪念印，14 天开文脉卡，全部无战力数值。

- **0.35×** 每城仅显示剪影与归属旗，长安保留双环。隐藏名字、人数和特效小物。
- **0.50×** 增加屏幕字号保底的单行城名。继续隐藏归属副签，只对选中城展示驻守摘要。
- **1.0×** 可显示城名与归属副签，按空间避让，近邻优先。
- **1.4×+** 显示地标细节、灯船、炊烟等小物，文脉仍由入口打开。

抽屉首屏依次显示城名、类型、归属、守备、驻守人数、合法相邻目标、我的军令与一个当前主操作。文脉、小传和城史放次层。需要贡献时先显示我方汇总和我的贡献，最多给三条贡献摘要，名单进入详情。

## 4. 60–100 人方案

**四阵营各 15–25 人，每区三城。** 用凉州、邺城、成都、建业作为起点，保持四区到中枢的行动成本接近。按预计活跃度均衡编组，避免自由扎堆。首轮用单班或有明确组织权限的试验组。跨班组队等班级隔离、教师分工和退出处理清楚后再开。

每天 180–300 道军令按目标城和阵营归并。对外只呈现每城每方的攻守总量及行动人数，对本人保留逐条回执。人数按去重学生数，军令数单列。同阵营重复投放的收益上限由玩法团队定。缺令可维持基础驻守，但不计主动贡献，也不能成为大阵营靠缺席堆出的额外战力。教师无需代令。缺勤可回归，新加入和转班优先在明确的回合边界处理，旧战报保留快照。默认不在地图上显示学生位置、名字或宠物队列。

| 场景 | 聚合方式 |
|---|---|
| 地图 | 固定 13 张主体加旗和路线。多人进军合成一条阵营路径，高亮当前所选行动，避免 100 个头像或 300 条动线。 |
| 城池抽屉 | 一行显示驻守人数、守备值和我方贡献。展开才看贡献前三，分别标明守城、支援等贡献类型。 |
| 阵营页与榜单 | 默认本阵营与本轮，支持按回合、城池及贡献类型筛选。手机用单列精简行，每页建议 10 条，我的记录固定可达。学生端优先阵营进度与个人复盘，个人榜使用试验昵称，教师明细另设权限。 |
| 教师台 | 按班或对局聚合锁令、结算和异常，提供暂停、重试、成员变更与导出。重置等不可逆操作须有范围提示与记录。目标是日常自动推进，教师只处理异常。 |

后端由 OpenCode 拍板。容量验证应覆盖截止前 100 人集中提交、重复提交、锁令竞争、失败重试、日报一致性和权限边界。每季约 8400 条军令只作为测试数据量级，是否上队列或归档以测量为依据。客户端同时用同城集中驻守、四路争长安与东南近共线路线构造最拥挤的场景。

## 5. 分阶段计划

1. **并行做四城垂直切片。** 复用已验收的长安和凉州，新增洛阳与建业。用同一套归属、选中、易主层和城池抽屉跑完整链路。以 64px 灰阶、0.35× 平板全图和 720×514 的 0.50× 手机横屏验收，检查城名、旗形和主操作。
2. **优先完成 5 节点真实试跑。** 8–12 人跑三回合，记录第三回合主动下令、能否解释结果、教师干预次数。合成数据的 60–100 人并发和满载视觉测试可同期跑，真实跨班测试排在后面。
3. **过门槛再扩。** 四城通过后扩齐 13 城主体和近景小物。五节点真实试跑通过、且四阵营模拟确认活跃差不会锁死局势后，再投入真实百人试点、四周赛季和完整 12 城正式底图。图鉴模板与标签设计可先行。文玉直购待获取节奏、旧商城并发与隐私边界验证后再启用。抽卡不排期。

## 6. 风险与不同意 OpenCode 的地方

- `CITY_DESIGN.md` 的制作优先级有「长安 + 4 起点 + 3 代表城」，其中凉州、建业与起点重复。建议明确首批为上述四个唯一城池，再补其余九座，防止重复排产。
- 原型报告写了全屏铺满、屏幕字号 13px 和暗衬改善。这些是原型基线，终审仍需核对手机实际字号、触控和百人聚合后的表现。注意东南直达线不能被读成经会稽中转。
- 王城身份与实际归属应分离。金环不能让学生误以为长安属于纸阵营，也不能让短暂选中态看起来像已经易主。末轮胜负和并列规则在正式美术状态定稿前由产品与 OpenCode 确认。
- 不主张为人数扩大增加可见对象，也不主张用城望数值或抽卡追赶留存。先验学生能否在一屏里选对城、看懂下令代价并理解结果。
